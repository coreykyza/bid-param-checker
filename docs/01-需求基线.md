# 招投标文件对照 — 需求基线 v2.0

> 来源：用户 2026-11-25 手工整理的《招投标文件对照》要求。本文档是开发与验收的唯一依据。

## 1. 本质目的

完全匹配的项目能**一次性核验通过**，完全不匹配的能**一次性挑出来**，有疑点的**提交人工确认**。

## 2. 总体要求

1. 一眼看得出每个项目（单元格）整体是否匹配；若不匹配，有多少条不匹配、多少条待确认。
2. 不匹配、不确定的能快速定位到**是哪一条**、哪里不匹配或哪里不确定。

## 3. 核验结果 C 列输出格式（严格要求）

### 3.1 全部满足
```
共10项：匹配8/正偏离2
```

### 3.2 部分满足
```
共10项：负偏离2/待确认3/匹配3/正偏离2
```
下方明细**只罗列负偏离和待确认**（匹配与正偏离不列明细）：
```
负偏离：
  1、【1、】内存大于等于4G->响应低于要求
  2、【二、1】课时大于等于8课时->响应低于要求
待确认：
  1、摄像头像素300w->响应相关内容未找到
  2、【3、】响应内容疑似匹配，置信度0.5
```

### 3.3 输出格式细则

| 规则 | 说明 |
|---|---|
| 统计行 | `共N项：负偏离X/待确认Y/匹配Z/正偏离W`（全部满足时为 `共N项：匹配Z/正偏离W`） |
| 明细行格式 | `序号 + 条目原文->结论` |
| 序号 | **必须严格同步招标原文的序号**：原文是 `1、` 就写 `【1、】`，原文是 `二、1` 就写 `【二、1】` |
| 无序号条目 | 投标条目本身没有序号时，**不加【】**，直接写内容 |
| 待确认置信度 | `置信度0.5` 格式，保留一位小数 |
| 标红 | 负偏离或待确认的**招标列（A 列）**对应条目标红高亮显示 |

## 4. 具体条目的状态定义

| 状态 | 判定依据 |
|---|---|
| **待确认** | ① 基于文本和语义匹配，在投标参数里找不到对应的内容；② 针对招标内容要求，投标内容有相关联的项目（基于语义匹配），但置信度较低 |
| **负偏离** | ① 针对招标内容要求，投标内容有相关联的项目（基于语义匹配），AI 判定为"严格不匹配"；② 内容要求里有明确参数要求，例如"不少于8课时，内存大于等于8GB"，属于很明确的不满足 |
| **匹配** | ① 内容要求为纯文本：先按**完全文本严格规则**（文本内容严格一致 A1=B1）；② 不满足严格规则时，按语义匹配且置信度达到要求 |
| **正偏离** | 内容要求里有参数要求，例如"不少于8课时，内存大于等于8GB"，在**大于**阈值时即满足（正偏离） |

### 4.1 数值边界规则（最易出错，单独强调）

| 招标要求 | 投标响应 | 判定 |
|---|---|---|
| 不少于8课时 / ≥8GB | 8课时 / 8GB | **匹配**（等于即满足） |
| 不少于8课时 / ≥8GB | 10课时 / 16GB | **正偏离**（大于即正偏离） |
| 不少于8课时 / ≥8GB | 6课时 / 4GB | **负偏离**（明确不满足） |
| 不超过150W / ≤150W | 145W | **匹配** |
| 不超过150W / ≤150W | 200W | **负偏离** |

## 5. 项目汇总状态定义（只有两档）

| 状态 | 定义 |
|---|---|
| **全部满足** | 所有条目都为匹配或正偏离 |
| **部分满足** | 存在条目为负偏离或待确认 |

## 6. 与 v1.x 的关键差异（重做原因）

| 项 | v1.x 现状 | v2.0 要求 |
|---|---|---|
| 判定粒度 | 模型只报偏离项，满足项丢弃，前端反推计数 | **每个条目必输出一个状态**，满足项也要输出 |
| 统计口径 | `满足X / 偏离Y / 待确认Z` | `匹配X / 正偏离Y / 负偏离Z / 待确认W`，全部来自条目状态聚合 |
| 序号 | 自造 `【一.1项】` | **严格同步招标原文** `【1、】`/`【二、1】` |
| 明细格式 | `【第N项】原文 → 理由` | `序号 + 原文->结论` |
| 明细范围 | 列了正偏离明细 | **只列负偏离与待确认** |
| 汇总档位 | 三档（多了"全部不满足"） | **两档** |
| 标红位置 | C 列结论 + A 列 | **只标 A 列（招标列）对应条目** |
| 待确认语义 | 混入"表述含糊" | 严格按第 4 节两条依据 |

## 7. 验收标准

1. 任取一行，C 列统计行的四个数字之和 == `共N项` 的 N。
2. 统计行各数字 == 明细实际行数（负偏离数、待确认数）。
3. 每条负偏离/待确认的序号能在 A 列原文中找到完全一致的字符串。
4. A 列中标红的条目 == C 列明细中列出的条目（不多不少）。
5. 一行内所有条目为匹配或正偏离时，C 列首行为"全部满足"且无明细。
